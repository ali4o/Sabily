# Sabily · سبيلي

يأخذ رابط فيديو طويل (بودكاست / محاضرة) ويُخرج مقاطع قصيرة 9:16 جاهزة للنشر،
كل مقطع بعنوان وكابشن يحتوي شرحاً مبسطاً ورابط الفيديو الأصلي عند التوقيت نفسه.

الإدخال: رابط واحد. المخرجات: ملفات `.mp4` + `.json` ولوحة محلية على
`http://localhost:6767` للمعاينة والنسخ والتحميل. النشر يدوي بالكامل.

---

## التشغيل

```bash
python -m venv .venv && .venv\Scripts\activate     # Windows
pip install -r requirements.txt
copy .env.example .env                              # ثم عدّل القيم
python -m app.main                                  # http://127.0.0.1:6767
```

### الفحص الشامل

```bash
python -m scripts.doctor                  # يفحص كل شيء ويطبع تقريراً
python -m scripts.doctor --quick          # بدون تحميل النماذج (أسرع)
python -m scripts.doctor --url "<رابط>"   # يفحص الرابط بدون تحميله
```

يغطي: البيئة والـ venv، الحزم ونسخها، بناء ffmpeg (libass/harfbuzz/fribidi)،
**أي خط استخدمه libass فعلاً** (يكشف الاستبدال الصامت)، الـ GPU وCUDA،
Whisper، Ollama والتوليد، منطق الاختيار، قاعدة البيانات، وقائمة المخرجات
على القرص. كل فحص معزول — فشل واحد لا يوقف البقية.

وهناك بوابتان مركّزتان إن أردت اختبار شيء بعينه:

```bash
python -m scripts.gate_arabic   # هل يرسم ffmpeg العربي بشكل صحيح؟
python -m scripts.gate_vram     # هل يمر Whisper ثم LLM بدون OOM؟
```

بدون واجهة:

```bash
python -m scripts.cli "https://www.youtube.com/watch?v=..." --clips 3
```

## المسار (Pipeline)

| # | المرحلة | الملف | يعمل على |
|---|---------|-------|----------|
| 1 | تحميل الفيديو + استخراج WAV | `pipeline/download.py` | شبكة |
| 2 | تفريغ صوتي بتوقيت الكلمات | `pipeline/transcribe.py` | **GPU وحده** |
| 3 | اختيار المرشحين (heuristics) | `pipeline/score.py` | CPU، بدون نموذج |
| 4 | ترتيب + عنوان + كابشن | `pipeline/llm.py` | LLM محلي أو API |
| 5 | تتبّع الوجه وتحديد القص | `pipeline/reframe.py` | CPU (OpenCV) |
| 6 | ترجمة مدمجة `.ass` | `pipeline/subtitle.py` | CPU |
| 7 | الرندر النهائي | `pipeline/render.py` | ffmpeg |

`pipeline/runner.py` هو المنسّق، و`jobs.py` طابور بمهمة واحدة في نفس الوقت.

### جاهزية النشر المباشر

- الصوت يُطبَّع إلى ‎-14 LUFS، وهو المستوى الذي تطبّعه المنصات عند التشغيل — فلا يخرج المقطع أخفت من غيره في التايملاين.
- كل سطر ترجمة يبقى على الشاشة مدة تكفي لقراءته (‏15 حرفاً/ثانية بحد أدنى 1.1 ثانية)، ويُمدّ في الصمت التالي لا فوق السطر الذي بعده.
- الاختيار يتجنّب أول 75 ثانية (`INTRO_SEC`) ويعاقب كلام الاشتراك والرعاة، فلا يخرج مقطع مقدمة أو دعاية.
- الرندر يستخدم NVENC تلقائياً إن وُجد، ويسقط إلى x264 عند الفشل.
- القاموس يتعلّم: كل تصحيح تكتبه في المحرر يُضاف إلى `assets/terms.json` ويُطبَّق على كل فيديو لاحق.

### كيف يُخفَّف الضغط على الجهاز

- Whisper يُحمَّل ويُستخدم ويُفرَّغ داخل دالة واحدة، ولا شيء آخر يلمس الـ GPU أثناءها.
- الـ LLM **لا يرى النص كامل** — فقط أفضل ~12 مرشحاً تنتجها الـ heuristics، وبسقف 400 كلمة للمقطع.
- `beam_size=5` و`vad_filter=true` في الـ ASR.
- تتبّع الوجه بـ OpenCV فقط (بدون mediapipe/jax)، بمعدل صورتين في الثانية، وبدون كتابة أي frame على القرص.
- مهمة واحدة في الطابور؛ البقية تنتظر.

### محرك اللحظات (Moment Engine)

الاختيار في المرحلة 3 يعمل على 5 مستويات — كلها heuristics محلية، وتعمل كاملة مع `LLM_PROVIDER=none`:

1. **فهم** نوع المحتوى (`lecture`/`lesson`/`podcast`/`interview` — تلقائي، أو `CONTENT_TYPE`/`content_type` للتثبيت)، ولكل نوع أوزان تقييم مختلفة (البودكاست يكافئ الخطاف والعاطفة، المحاضرة تكافئ القيمة والاكتمال).
2. **تقسيم** النص إلى مواضيع (تشابه مفردات، بدون embeddings) حتى لا يخرج مقطعان عن نفس الفكرة.
3. **اكتشاف** نوع اللحظة (سؤال، قصة، فكرة محورية، قول قوي، معلومة مدهشة، منهجية، رأي...) بمعجم عربي.
4. **ترتيب** بثمانية معايير: القيمة، الاستقلال عن السياق (standalone)، الخطاف، الوضوح، الاكتمال، الأثر العاطفي، الجدة، قابلية المشاركة.
5. **تهذيب** الحدود: توسيع السياق (سؤال التمهيد + جملة الختام) وتقليم الحشو من البداية («طيب يعني») والتشويق من النهاية — دون حذف أي معنى.

كل مقطع يحفظ في `meta`: `moment` و`topic` و`reasons` (لماذا اختير) و`scores` (المعايير الثمانية) — اعرضها من JSON المقطع.

### التبديل بين المحلي والـ API

سطر واحد في `.env`:

```
LLM_PROVIDER=ollama   # محلي (الافتراضي)
LLM_PROVIDER=gemini   # أو openai — مع LLM_API_KEY
LLM_PROVIDER=none     # بدون نموذج إطلاقاً: عنوان وكابشن من النص مباشرة
```

إذا فشل النموذج أو انقطع، المسار **لا يتوقف**: يُنتج المقطع بعنوان وكابشن heuristic
ويُسجَّل تحذير في الـ log.

## المخرجات

```
outputs/{job_id}/clip_01.mp4     الفيديو الجاهز
outputs/{job_id}/clip_01.json    العنوان، الكابشن، الرابط الموقوت، التوقيتات، النص
```

الكابشن يُبنى هكذا: شرح مبسط سطرين → رابط الفيديو الأصلي مع `?t=` عند بداية المقطع → 3-5 وسوم.

كل مقطع يُرندر بالأبعاد المختارة بالضبط (`HD ٧٢٠` / `FHD ١٠٨٠` / `2K ١٤٤٠`)،
ويُتحقق من الأبعاد بعد الرندر — أي mismatch يُفشل المهمة بدل تسليم جودة خاطئة.
عناصر الظهور (الشعار/الهاشتاق/النص السفلي) تُضبط per-job من نموذج الإدخال
وper-clip من محرر المقطع، وتُحفظ في `meta` لتُعاد في أي `rerender`.
صفحة التصور التفاعلي: `/static/video-mockup.html`.

## API

| Method | Path | الوظيفة |
|--------|------|---------|
| POST | `/api/jobs` | `{url, clips?, lang?, aspect?, quality? (HD/FHD/QHD), content_type? (auto/lecture/lesson/podcast/interview), brand_watermark?, show_source?, burn_subtitles?, keep_source?}` → يبدأ مهمة |
| GET | `/api/jobs/{id}` | حالة المهمة + مقاطعها |
| GET | `/api/jobs/{id}/events` | SSE لتقدّم المعالجة |
| GET | `/api/clips` | كل المقاطع (تبنى منها كروت الواجهة) |
| PATCH | `/api/clips/{id}` | تعديل العنوان/الكابشن/الترجمة والمواضع وعناصر الظهور (يتعلّم القاموس) |
| POST | `/api/clips/{id}/rerender` | إعادة بناء MP4 من التعديلات المحفوظة بنفس الجودة الأصلية |
| DELETE | `/api/clips/{id}` | حذف مقطع |
| DELETE | `/api/clips?job_id={id}` | حذف مقاطع مهمة واحدة |
| DELETE | `/api/jobs/{id}/source` | حذف الفيديو الأصلي لتوفير المساحة |
| GET | `/api/health` | النموذج والجهاز المستخدمان |
| POST | `/api/server/restart` | إعادة تشغيل السيرفر (زر أعلى اليسار) |
| POST | `/api/server/shutdown` | إيقاف السيرفر (زر أعلى اليسار) |
| GET | `/api/stats` | إحصائيات: المهام والمقاطع والدقائق والمساحة |
| GET | `/api/settings` | كل مفاتيح `.env` القابلة للتحرير مع أنواعها |
| PUT | `/api/settings` | حفظ مفاتيح (تُطبق بعد إعادة التشغيل) |

## حدود معروفة (بصراحة)

- **لا يوجد auth**: الخادم مربوط بـ `127.0.0.1` فقط. لو عُرِض خارج الجهاز، أضف auth أولاً.
- **متحدث واحد**: التتبّع يختار أكبر وجه؛ الحوار بين شخصين سيقفز بينهما.
- **دقة الكشف**: Haar أمامي + جانبي (profile) افتراضياً مع جسر للالتفاتات القصيرة (`FACE_HOLD_SEC`) وانحياز للوجه الأوسط (`FACE_CENTER_BIAS`)، وبدون أي تبعية جديدة. للأفضل: نزّل `face_detection_yunet_2023mar.onnx` من opencv_zoo إلى `data/models/` وسيستخدمه تلقائياً.
- **غياب الوجه**: إن قلّت تغطية الوجه عن `FACE_MIN_COVERAGE` يُعرض **الفريم كاملاً** فوق خلفية ضبابية (`FACE_BLUR`) بدل قص شريحة عمياء.
- **ضبط القص يدوياً**: فعّل «ضبط القص أولاً» في الواجهة لترى 6 فريمات حقيقية قبل المعالجة، اسحب مربع القص وحدد عرضه، ثم اعتمد — يُقفل القص لكل المقاطع (وضع manual مضمون).
- **القص الديناميكي** يعتمد على تعبير `if` في ffmpeg بحد 20 نقطة تغيير؛ عطّله بـ
  `DYNAMIC_CROP=false` إن ظهر أي اهتزاز.
- **الترجمة المدمجة** تعتمد على بناء ffmpeg يحتوي libass+fribidi+harfbuzz — بوابة 1 تتحقق من ذلك.
- **النشر**: خارج النطاق بالكامل وبشكل متعمّد.
- **الحقوق**: استخدمه على محتوى تملكه أو لديك إذن به.
- **النشر على سيرفر**: غير مطبّق حالياً — المشروع محلي بالكامل عن قصد.
